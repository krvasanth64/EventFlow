# EventFlow V1.1 — On-Air Console & Award Planner

Updated: 2026-11-04.

## Why V1.1

All nine V1 functional acceptance checks were **reported passed by the Windows/Tailscale host user** (five mixed programs, ordering/timings, MP3, MP4 seeking, mobile playback, same-event exclusive editor, independent-event editing, live start/finish/skip, A4 agenda PDF).

V1.1 adds on-air media preview/controls and a separate ordered award-winner list. This is **not yet device-accepted** and does not replace the existing JSON data.

## On-Air operation

- Open an event, choose **Live Control**, and acquire **Edit This Event** to operate.
- The current program shows its local audio/video preview with browser playback controls, elapsed time, remaining scheduled duration, projected event finish, delay/early indicator, and a continuously recalculated program timeline.
- **Play / Start:** program state becomes Running; media playback is requested in this browser.
- **Pause:** freezes program elapsed time, and pauses browser media playback.
- **Resume:** resumes elapsed-time tracking and attempts to resume media.
- **Stop & Reset:** stops this program, clears its timer and resets the local media to zero. Use Play / Start again to replay. This does not mark the program completed.
- **Finish & Next:** marks the active program Done, records actual end and advances to the next remaining program.
- **Skip:** skips a pending/stopped program; actual end is stored.
- A live editor lock and revision number are checked on every state transition. A second user cannot overwrite the operator's action.

**Media behavior:** The preview/player operates on the browser where Play is pressed. It **does not automatically synchronize audio or video playback across viewers**. Other viewers see the on-air status and dynamic schedule but play media locally if desired. Browsers can block playback without a user gesture; use the player's built-in Play button as fallback. Web URLs open separately if a website prevents embedding; host-linked paths are recorded as references.

**Time reforecast:** The agenda retains its original planned times. When an event is live, the timeline uses actual completed timestamps, elapsed and remaining time for the current program, real current time, and each program's changeover gap to calculate revised start/end and expected finish. If an event runs late, subsequent start times shift; no automatic media advancement occurs.

## Award winner planning

- Open **Award Planner** from the left sidebar or mobile bottom menu.
- Choose event (same global Event selector as Program Planner).
- Acquire the event edit lock; add awards by category, award title, winner name, recipient details, presenter, and instructions.
- Reorder award presentations with drag-and-drop or ↑/↓ touch-friendly controls.
- Mark an award Presented / Reopen, or edit/delete records.
- Export the award list using **Print / PDF** and select the browser's Save as PDF destination.
- Awards are saved inside the existing JSON database as a separate `awards` array linked to Event IDs.
- Reordering awards does not alter chronological programs, and vice versa. Both share the one-editor-per-event lock.

## Data continuity

Existing `runtime/data.json` continues to work. Server initializes a missing `awards` array in memory when loading an old database and persists it when a change is made. No reset or data import is needed. Keep the runtime folder out of the public repository.
