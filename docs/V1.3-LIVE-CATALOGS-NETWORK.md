### Predesigned program types

Solo Dance, Group Dance, Drama, Magic Show, Stand-up Comedy, Speech, Karaoke Singing, Solo Singing, Group Singing, Instrumental Music, DJ Performance, Mime, Awards Ceremony, Welcome Address, Vote of Thanks and Other.

The old stored program types remain accepted for compatibility. Event dropdown settings let you enable/disable or add event-specific values.

### Live reorder rules

During live operation, the editor can change the displayed order of any program. Saved actual timestamps, status and stable program IDs remain attached to the program. The actively playing media is not intentionally stopped or restarted by a reorder. This uses a single-editor-per-event lock and event-revision checks.

On desktop, drag a program by the handle and drop onto its new row; Up/Down buttons provide a fallback and work on mobile. Reordering changes the agenda, not the award presentation order.

### Media archive behavior

A replacement upload gets a unique filename. If it replaces a managed file, the old source path is appended to `sourceArchive` in JSON. Archiving does not physically erase the bytes. Media and reading-script archives are separate. The original source can still be accessed by authenticated sessions; manual cleanup is not included in this release.

### Live playback and timing

For on-stage local media, EventFlow tries to start playback before starting the program clock. If a remote row is started but browser autoplay blocks playback, EventFlow pauses the timer and prompts the operator. Manual browser media pause and end also attempt to pause the event clock.

For an external web URL, the app **cannot verify playback in the other tab**. Start the program clock explicitly once the external media or live speech begins. Media output is only on the operator's browser, not a broadcast to all viewers.

## Windows PC — essential restart and connectivity check

The reported diagnostics showed **no TCP listener on port 8765** and `http://127.0.0.1:8765/api/health` refused connections. This is a missing/running-host problem, regardless of Tailscale and firewall configuration.

1. Stop EventFlow, copy `D:\EventFlow\runtime` to a separate backup folder, pull code from GitHub.
2. Run JavaScript syntax checks and `npm test`.
3. Start `D:\EventFlow\start-eventflow.bat` and **leave that window running**.
4. From a second PowerShell terminal on the *host*, verify:
   ```powershell
   Invoke-RestMethod http://127.0.0.1:8765/api/health
   Get-NetTCPConnection -LocalPort 8765 -State Listen
   ```
5. Expected health version: `1.3.0`. Expected listening LocalAddress: `0.0.0.0` or equivalent. If not running, read the error message in the launcher window before doing further network tests.
6. On another **trusted LAN** PC, use the host's real IPv4 address. For the previously supplied host address:
   ```powershell
   Test-NetConnection 192.168.1.140 -Port 8765
   ```
   Then open `http://192.168.1.140:8765`.
7. If localhost works but LAN fails: inspect Windows network profile, `scripts/allow-lan-firewall.ps1` rules, antivirus firewall and LAN/VLAN routing. Do not use `192.168.1.XXX` literally; use the real address.

## Tailscale internet distinction

- **Serve**: `tailscale serve --bg --https=443 http://127.0.0.1:8765` exposes EventFlow only to members/devices authorized in the same Tailscale network.
- **Funnel**: separately exposes a service to the public internet, including users who are *not* connected to Tailscale. This is not enabled by EventFlow and is not recommended for the lightweight temporary login without first setting a unique strong admin password and reviewing public exposure.

A Serve status message shows that Tailscale is configured to proxy; it does **not** prove EventFlow is running or another device can reach it.
