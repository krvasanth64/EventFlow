## Windows: verify your existing backup

Run in another PowerShell window. Keep the regular EventFlow test host unchanged while **verifying** a backup. Do not run the restore into a folder that already exists.

```powershell
cd D:\EventFlow-V14-Test

# Set this to the actual ZIP file you downloaded in Reports:
$zip = "D:\Downloads\EventFlow_FULL_YYYY-MM-DD.zip"

node scripts/verify-backup.js --verify $zip

# A completely new, empty target path:
$recovery = "D:\EventFlow-Restore-Rehearsal-" + (Get-Date -Format "yyyyMMdd-HHmmss")
node scripts/verify-backup.js --restore $zip $recovery
```

The verifier reports counts, number of media files, archive size and SHA-256. It must not display user passwords or personally identifying participant data. A failed check should abort recovery.

## Windows: test the restored runtime separately

Stop any process already using port 8767 first. Run the recovered app in a different terminal, with a distinct data directory.

```powershell
cd D:\EventFlow-V14-Test
$env:HOST = "127.0.0.1"
$env:PORT = "8767"
$env:EVENTFLOW_DATA = $recovery
node server.js
```

Open http://127.0.0.1:8767. Sign in using an existing account from the backup. Check the original event count, permanent P/A codes, participants and playable uploaded media. Keep the restored runtime isolated; never point two Node servers to the same data directory.

## Dependency reproducibility — current blocker

A local `npm install` generated **untracked** `package-lock.json` in the Windows test checkout. Because it was not committed to GitHub, CI still resolves dependencies independently with `npm install`. The lock must be reviewed and committed before Coolify production deployment.

Recommended safe workflow on the Windows test branch:

```powershell
cd D:\EventFlow-V14-Test
npm install --package-lock-only --ignore-scripts
npm audit --omit=dev --audit-level=moderate
npm ls exceljs uuid tmp
git status --short
# After reviewing the lockfile and audit, add and commit only the lockfile:
git add package-lock.json
git commit -m "build: lock validated EventFlow runtime dependencies"
git push origin feature/live-console-v14-foundation
```

Do not run `npm audit fix --force` as a shortcut. The 2 moderate findings must first be identified and checked for compatible remediation. Once a lockfile is committed, change CI and Docker builds to `npm ci`.

## Coolify HTTPS staging

- Use the feature branch only and a **separate** persistent volume mounted at `/data`.
- Container must run as a single writable UID 10001 instance.
- Set `EVENTFLOW_SECURE_COOKIES=1`.
- Set `EVENTFLOW_PUBLIC_ORIGIN=https://your-staging-domain` to the **exact browser origin**, without a trailing slash. This optional protection rejects cross-site mutation requests when configured.
- Publish through HTTPS only. Do not expose plain Node port 8765 directly to the public Internet.
- Confirm actual DJ media playback on the controller's machine and LED updates on a second machine. SSE delivers state, not an audio/video stream.
- Restart Coolify and verify events and media survive; rerun an isolated restore rehearsal against the staging data.
- Limit public rollout until rate limiting, authentication, session management and the npm audit have been reviewed.
