# EventFlow V1.5.1-beta — slow-internet performance over Tailscale Funnel

## Changes implemented

1. **Gzip JSON responses:** JSON objects larger than 1 KB are gzip-compressed when the browser advertises gzip. Compression uses `Z_BEST_SPEED` to minimize CPU. Authentication, permissions, revisions, no-store, and API content remain unchanged. Binary ZIP, PDF, Excel and media streams are not compressed.
2. **Immutable versioned static assets:** The server sends `Cache-Control: public, max-age=604800, immutable` only for versioned public JS/CSS assets (those with `?v=...`). The HTML app entrypoint, unversioned assets, API, uploaded media, and auth are always `no-store`.
3. **PWA static-only cache:** A service worker caches only same-origin JS/CSS app assets on successful fetch; dynamically authenticated event data, employee/participant information, live states, media, SSE, PDFs and import/export endpoints never enter browser persistent cache. Older EventFlow SW caches are removed on activation.
4. **Live synchronization reduction:** SSE continues to provide immediate live updates. On an update for the active event, the frontend fetches only current event details instead of both event list and event details. In-flight refresh requests are coalesced; the redundant 15-second event-list polling is removed. A fallback refresh checks the stream every 30 seconds and resynchronizes if disconnected or if 120 seconds pass without a refresh. Switching a tab back to foreground forces a fresh server fetch.
5. **No offline editing mode:** Cached static assets may load when a connection is unavailable, but event/award/program editing still needs an authenticated server; stale event data must never be used to authorize changes.

## Windows update

Stop the current `node server.js` process (Ctrl+C in the actual EventFlow console). Do not run another Node process concurrently against the same JSON database.

```powershell
cd D:\EventFlow-V14-Test

$backup = "D:\EventFlow-V14-Backup-" + (Get-Date -Format "yyyyMMdd-HHmmss")
Copy-Item "D:\EventFlow-V14-Data" $backup -Recurse

git pull --ff-only origin feature/live-console-v14-foundation
npm ci
node --check server.js
node --check public/app.js
node --check public/sw.js
node --check public/v21.js
npm test

$env:HOST="127.0.0.1"
$env:PORT="8766"
$env:EVENTFLOW_DATA="D:\EventFlow-V14-Data"
node server.js
```

In Chrome, refresh with Ctrl+Shift+R once so the new service worker and versioned static assets are installed. Subsequent navigations reuse the scripts. Check DevTools → Application → Service Workers and Cache Storage for public static assets only.

## Measure real-world speed

Run this in another PowerShell window to record local API response time:

```powershell
1..5 | ForEach-Object {
  $result=Measure-Command {
    Invoke-RestMethod http://127.0.0.1:8766/api/health | Out-Null
  }
  "Local health: {0:N0} ms" -f $result.TotalMilliseconds
}
```

On a different internet-connected device, open the Funnel HTTPS URL, measure the first page load, then reload and navigate around the application. Compare subsequent visits after the static cache is installed. This optimization primarily improves repeat visits and JSON-heavy events. **It cannot remove the Tailscale Funnel relay limit or the Windows computer's upload speed**.

## Important safety and networking notes

- The Funnel HTTPS URL is public: **Cloudflare Access is NOT protecting this address**. Only test with non-sensitive sample data until authentication and npm security review are complete.
- Tailscale Funnel bandwidth is intentionally constrained; for consistent performance with multiple event devices prefer private Tailscale Serve, or move to a dedicated HTTPS application host when ready.
- Uploaded media remain uncached and may be slower over Funnel; preload/download media on the designated DJ PC before the event, or run the DJ console locally to avoid relying on WAN audio streaming.
- Keep only **one EventFlow server** writing to the existing JSON data directory.
- Coolify deployment, 2 moderate npm audit vulnerabilities and full public-security acceptance remain pending.
