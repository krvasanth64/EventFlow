# EventFlow V1.4.9 beta — Dynamic Timeline pagination and compact PDFs

## Dynamic Timeline / Live running order

- Default **10 program rows** per page whenever a different event is selected.
- Page sizes: **10, 20, 30, 50, 100, 200, ALL**.
- On first opening a category/event, automatically select the page containing the current `running` or `paused` program.
- If none is running, open the page containing the first `pending` / `ready` / `stopped` upcoming program.
- Previously completed programs remain searchable via **Previous** pages. The default opening page should not be a completed-only page when an active/upcoming program is available.
- When the on-air program changes, automatically follow the new live position. Ordinary live-data revisions do **not** unexpectedly reset the operator's manually selected page.
- Controls: page-size dropdown, Previous, Next, page counter, Go to Live, showing N–M of total.
- Up/down and drag-and-drop actions continue to refer to permanent UUIDs, not page index; reordering across pages can use Up/Down controls.
- Skipped programs remain in the separate Skipped Programs section; they do not count toward the paginated running order.
- The timeline shows a **concise readiness indicator** for upcoming items, such as `1/3 Ready` or `0/0 Ready`. This status is informational and uses the checked-in values from each Program participant child table.

## Backstage Preparation

- This is the **only place** showing the full `Upcoming 4 · Participant readiness` checklist.
- The duplicate full checklist under Live Control has been removed; Live Control shows only count badges.
- Participant check-in, roster changes and readiness updates still operate through the existing API and synchronize via event revision updates.

## Program and Award PDF reports

- PDF body row height is automatically calculated from the selected **font size** and measured wrapped text height.
- Compact vertical cell padding scales with font size; there is no rigid minimum 23-point body row height.
- Long cells may wrap; extremely tall rows are bounded to fit the printable page and use ellipsis rather than flowing into headers/footer.
- Table header height also scales modestly with the font size.
- User-selected columns, widths, sequence, A4 portrait/landscape and fixed P#### / A#### identifiers are unchanged.

## QA status and local acceptance

Automated tests cover stage-first page selection, page-size choices, suppression of duplicated participant panel, and PDF row-density comparison. Manual browser acceptance is still necessary for page controls, touch/mobile navigation, drag-drop on a later page and PDF preview print geometry.

### Windows test steps

Stop the existing port 8766 EventFlow process with `Ctrl+C` in its own console before restarting.

```powershell
cd D:\EventFlow-V14-Test
git pull --ff-only origin feature/live-console-v14-foundation
npm ci
node --check public/v19.js
node --check report-pdf.js
npm test

$env:HOST = '127.0.0.1'
$env:PORT = '8766'
$env:EVENTFLOW_DATA = 'D:\EventFlow-V14-Data'
node server.js
```

Open `http://127.0.0.1:8766`, refresh with `Ctrl+Shift+R`. Use the demo event and add more than 20 programs to validate pagination across completed/live/upcoming boundaries. Mark one participant ready on Backstage; return to Live Control and confirm the summary count.
